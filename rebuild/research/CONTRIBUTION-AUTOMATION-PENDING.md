# Γ.Α.Σ. Αρχέλαος — Αρχιτεκτονική, πρόοδος και εκκρεμότητες αυτοματισμού
Ενημέρωση: 2026-11-02 · Repository: dizigs/archelaos-site · [PR #37](https://github.com/dizigs/archelaos-site/pull/37)

## Στόχος
Να αναλύονται με ελάχιστη χειροκίνητη εργασία οι συνεισφορές, τα επιτρεπόμενα αρχεία του κοινόχρηστου Google Drive, τα αρχεία που παραδίδει ο διαχειριστής και οι δημόσιες ειδήσεις. Για κάθε **γεγονός** να γίνεται έρευνα στο διαδίκτυο, διασταύρωση και σύνδεση με υπάρχοντα άρθρα, ιστορικά γεγονότα και πρόσωπα. Εφόσον τεκμηριώνεται, να παράγεται νέο δημοσίευμα ή να ενημερώνεται το υπάρχον, μαζί με τα σχετικά βιογραφικά. Αποφυγή διπλοεγγραφών, σύγχυσης ομωνύμων και επινοημένων επιτευγμάτων.

## 3. Πλήρης κατάλογος πηγών εισόδου και κανόνας αξιολόγησης

| Είσοδος | Μηχανισμός | Περιεχόμενο |

| Επίσημες ομοσπονδίες και διοργανωτές | APIs/feeds όπου υπάρχουν, αλλιώς ελεγχόμενη αναζήτηση | Επιβεβαιωμένα αποτελέσματα, κατατάξεις, συμμετοχές |

| Αρχεία κοινόχρηστου Drive «ΓΑΣ Αρχέλαος» | Drive changes/revision polling + permissions check | Πρακτικά, φωτογραφίες, έγγραφα, αρχεία |

| Απευθείας εισαγωγές διαχειριστή | Explicit uploaded file event | PDF/DOCX/TXT/XLSX/ICS + metadata |
| Βάσεις site (Hall, news, event ledger, 70 στιγμές, ιστορία τμημάτων, Φωνές) | Git change event / canonical ID index | Υπάρχον γεγονός/πρόσωπο και συσχετίσεις |
| Ημερολόγια και επίσημα αγωνιστικά προγράμματα | ICS/feed updates | Αγώνες και προγραμματισμένες δραστηριότητες |
| Συνεντεύξεις/μαρτυρίες | Consent-aware transcript import | Πρόσωπα, αφήγηση, ιστορικά γεγονότα |
| Φωτογραφίες/λεζάντες | Metadata/caption analysis where permitted | Πρόσωπα, εποχή, γεγονότα, τεκμήρια |

**Πολιτική ειδήσεων:** τα δημοσιεύματα που αφορούν πραγματικά τον Γ.Α.Σ. «Αρχέλαος» Κατερίνης αποτελούν αποδεκτές πηγές αυτόματης επεξεργασίας χωρίς έγκριση ανά δημοσίευμα. Διασταύρωση/προσωρινή αναμονή μόνο για αντιφάσεις, ομωνυμίες, άγνωστες ταυτότητες ή υψηλής βαρύτητας ισχυρισμούς. Το περιεχόμενο των ειδήσεων αναδιατυπώνεται, με σύνδεσμο στην πηγή, χωρίς αντιγραφή άρθρου. Το μπάσκετ ΣΦΚ Πιερικός Αρχέλαος δεν αποδίδεται αυτόματα στον ανεξάρτητο ΓΑΣ.

**Πολιτική φωτογραφιών:** ανακτούμε metadata και υποψήφια φωτογραφία από το ίδιο άρθρο (featured/og:image), επισημαίνουμε URL και δημιουργό/πηγή. Τοπική αναδημοσίευση μόνο αν προκύπτει δικαίωμα χρήσης (π.χ. φωτογραφία ιδιοκτησίας συλλόγου, άδεια, κατάλληλη ανοικτή άδεια). Διαφορετικά δοκιμάζουμε επιτρεπόμενο embed ή νόμιμη εναλλακτική. Αναφορά πηγής από μόνη της δεν αποτελεί άδεια. Δεν απαιτείται manual approval για εικόνες των οποίων τα δικαιώματα είναι σαφή.

## 4. Μία βάση και αμφίδρομες συνδέσεις, χωρίς κυκλικές ενημερώσεις

**Οντότητες:** `Person`, `Event`, `Article`, `Source`, `Department`, `Contribution`, `MediaAsset`, `Interview`, `TimelineItem`. Κάθε οντότητα έχει μόνιμο ID, ιστορικό αλλαγών, πηγές, status, χρονική ακρίβεια και version. Σχέσεις: Event↔Person, Event↔Article, Event↔Department, Event↔TimelineItem, Person↔Interview, Source↔every supported claim, MediaAsset↔Article/Event. Η **πηγή αλήθειας** είναι το κανονικοποιημένο μητρώο και τα εγκεκριμένα IDs, όχι κάθε προβολή HTML/JSON ξεχωριστά.

Η αμφίδρομη λειτουργία αφορά **πλοήγηση και συσχέτιση**: νέο γεγονός ενημερώνει το χρονολόγιο, τη σχετική είδηση και τα συνδεδεμένα βιογραφικά· άνοιγμα προσώπου αποκαλύπτει τα τεκμηριωμένα γεγονότα και τις ειδήσεις του. Όταν μια νέα πηγή διορθώσει στοιχείο από οποιαδήποτε είσοδο, το ίδιο canonical record ενημερώνει όλες τις προβολές. Οι παραγόμενες σελίδες δεν γράφουν ανεξάρτητα πίσω στη βάση· αυτό θα δημιουργούσε κυκλικές αλλαγές και διπλότυπα.

**Χρονολόγιο:** καρτέλες μόνο με τίτλο/ημερομηνία και popup πλήρους γεγονότος, πηγή, σχετικές ειδήσεις και πρόσωπα. Υποστηρίζει ιστορικές περιόδους (έτος/σεζόν/δεκαετία) καθώς και ακριβείς ημερομηνίες· γεγονότα χωρίς αξιόπιστη χρονολόγηση δεν επινοούν ημερομηνία.

## 5. Απρόσκοπτη αυτοματοποίηση χωρίς κουμπιά

1. Trigger: νέα ή αλλαγμένη είσοδος (Gmail/Drive poll ή push event, upload, scheduler δημόσιων πηγών, Git commit), με checkpoints και dedupe keys.
2. Analyze: ασφαλής εξαγωγή κειμένου, ανίχνευση γεγονότων/αποτελεσμάτων/προσώπων, δημιουργία leads.
3. Research: ιστοσελίδες/ομοσπονδίες, πλήρης έρευνα πηγών, privacy-safe search, πηγές ανά συγκεκριμένο ισχυρισμό.
4. Match: ημερομηνία, άθλημα, διοργάνωση, αντίπαλοι, σκορ, person IDs, παλιές εγγραφές. Ακριβείς αντιστοιχίσεις ενισχύουν την υπάρχουσα οντότητα.
5. Propose/commit: τεκμηριωμένα χαμηλού ρίσκου records εντάσσονται σε αυτόματη διαδρομή δημοσίευσης με κανόνες· ασάφειες σε ανθρώπινο review, χωρίς να μπλοκάρουν την υπόλοιπη ροή.
6. CI: ελέγχονται schemas, duplicate detection, security, integrity, accessibility, Lighthouse και build. Αποτυχία σταματά το **συγκεκριμένο** release, όχι όλο το intake.
7. Publish: υπό εγκεκριμένη branch/merge πολιτική, Cloudflare Pages συνθέτει και δημοσιεύει το dist από canonical data.
8. Observe: κάθε στάδιο έχει audit record, alerts, retry/backoff και idempotent rerun· ενημέρωση όλων των public views μετά από επιτυχία.

**Πραγματική κατάσταση (2026-11-02):** ο κώδικας extraction/search skeleton/matching/tests υπάρχει στο PR #37 και πέρασε offline CI, αλλά δεν έχει υλοποιηθεί η πλήρης trigger→fetch attachment→research→source verification→canonical write→auto merge→production pipeline. Οι ήδη προγραμματισμένοι έλεγχοι Gmail/Drive/ειδήσεων είναι είσοδοι που πρέπει να ενοποιηθούν — δεν αποτελούν από μόνοι τους end-to-end αυτοματοποίηση. Firecrawl API key παραμένει εκκρεμότητα και μπορεί να αντικατασταθεί από άλλη επιτρεπόμενη λύση για ερευνητικά queries.

## 6. Επόμενο τεχνικό ορόσημο
Πρώτα idempotent ingestion Gmail + Drive + admin files με ιδιωτικό receipt και εξαγωγή κειμένου. Δεύτερο κεντρικό registry events/persons/articles/sources, τρίτο μονάδα web corroboration και photo rights, τέταρτο automatic low-risk commit/release σε preview, τέλος guarded production autopublish και ειδοποίηση μόνο σε exceptions.
