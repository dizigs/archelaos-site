# Native Apps Script → Brain capability port (OFF)

This is **client code only**, introduced in the existing Automation Bridge PR #272. It is NOT imported or mounted into the installed `archelaos-automation-bridge` Worker and does not add a route, Worker, cron, config binding or provider API call. It does not complete the actual Google provenance / oauth verification needed for a live delivery.

`src/native-brain-port.mjs` offers the three privileged ports `readBrainCapabilities`, `submitToBrain` and `readBrainReceipt` for safe composition with the existing `relayAppsScriptReceipt` and `sendReadOnlyReceipt`. **Other ports remain the existing source-owner responsibility**: trusted provider receipt readback, durable `claimDelivery` and `finalizeDelivery`, controls, independent audit. The port requires both an explicit trusted `enabled:true` and `BRIDGE_BRAIN_RELAY_ENABLED=true`; neither is currently configured in the installed Bridge. It requires a native `BRAIN_PRIVATE` binding, separate `BRAIN_APPS_SCRIPT_INTAKE_KEY` and `BRAIN_CAPABILITY_RECEIPT_KEY` secrets, and a pinned Brain SHA.

Protocol is exactly existing Brain's `apps-script-v1` HMAC GET /v1/capabilities/apps-script, POST /v1/intake/apps-script and POST /v1/apps-script/readback, all through `env.BRAIN_PRIVATE.fetch`. Health identity must match exact approved SHA and have AI OFF. The capability must match the hash of that SHA. The Brain's Apps Script intake response is **unsigned**: only after independently HMAC-verified, source-matched **durable readback** can a caller receive the ACK. Loss, timeout, tampering, cross-source identity, stale signature, non-canonical event and unexpected fields fail closed. No automatic retries after UNKNOWN. Tests use synthetic data and cannot attest real Cloudflare binding or Google provenance.
